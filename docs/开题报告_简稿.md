# 多Agent共享记忆驱动的工业软件故障诊断知识图谱构建

> 开题报告简稿 | 2 分钟汇报版

---

## 问题

工业软件故障诊断的知识瓶颈：经验散落在人脑、工单、日志里，相似故障反复从零排查，旧知识随系统迭代快速过时。现有知识图谱靠专家手工构建，更新滞后，无法自动从新故障中学习。

**核心问题**：怎么让系统在处理故障的同时，自动把诊断经验沉淀成可演化的知识图谱？

---

## 思路：诊断即建图

不先建 KG 再用 KG。而是让多 Agent 协作诊断故障的过程本身，就是知识图谱的构建过程。每处理一个故障，KG 就自动增长一分。

技术基础：已有的共享记忆模块（MemoryStore + 语义检索 + 意图门控 + evidence_chain + SafeSieve），将其适配到故障诊断场景。

---

## 一、故障知识的结构化存储

用 `MemoryUnit` 作为知识图谱的基本单元——一条记忆就是一个 KG 节点：

```
故障案例 MemoryUnit
├── summary:     "订单服务响应超时，根因：缺少联合索引"
├── content:     {诊断步骤, 修复方案, 监控指标}  ← JSON
├── tags:        ["database", "performance", "timeout"]  ← 故障分类
├── evidence_chain: [m1, m2, m3]  ← 因果推导链路
├── embedding:   384 维语义向量  ← 症状相似度匹配
├── memory_type: result/strategy/evidence/fact/error
└── abstraction_level: 0=案例 / 1=诊断模板 / 2=诊断原则
```

`evidence_chain` 是关键——它把"症状→中间原因→根因"的推导链路固化下来。比如"服务超时"→"连接池满"→"慢查询堆积"→"缺少索引"，这条链就是知识图谱中的因果路径。

存储引擎：SQLite 存元数据 + FAISS 存 384 维语义向量，三路检索（关键词/标签/语义）并行，综合排序。

---

## 二、故障案例的智能复用

新故障来了不是从零开始，而是三级匹配：

| 匹配度 | 症状相似度 | 策略 |
|--------|-----------|------|
| 高度相似 | cos ≥ 0.85 且同故障类 | 整案复用——"同一个故障又出现了"，直接返回诊断方案 |
| 中度相似 | cos 0.68–0.85 且同故障类 | 复用诊断策略模板，LLM 只填空差异字段——"同类故障，表现略有不同" |
| 低度相似 | cos < 0.68 | 注入相关案例作为提示，从零诊断 |

**意图门控防止误用**：数据库死锁的诊断模板绝不能套用到网络超时上。`task_intent.py` 将故障分为 database/network/config/code/resource 等大类，严格意图只同类型复用。对抗验证确保该机制有效。

## 三、知识图谱的自演化

三个层级的自动归纳：

```
Level 0 — 具体故障案例（自动记录）
  "2024-03-15，MES订单超时，根因：orders 表缺少联合索引"

Level 1 — 诊断策略模板（同类案例 ≥3 自动聚类生成）
  "数据库连接池类故障诊断模板":
    Step 1: 查连接池使用率 → Step 2: 分析慢查询 → Step 3: 检查索引 → Step 4: 验证修复

Level 2 — 诊断原则（LLM 跨模板归纳）
  "数据密集型服务响应延迟，优先排查数据层（连接池→慢查询→索引），再查应用层"
```

**SafeSieve 质量闭环**：每个模板被复用后追踪结果——诊断成功则权重升高，连续失败则自动降权淘汰。知识图谱不需要人工维护，靠诊断反馈自我校正。

---

## 创新点

1. **诊断即建图**：KG 不是前置条件而是诊断过程的副产品
2. **因果链匹配**：复用案例不只看症状像不像，更看"症状→根因"的因果结构是否同构
3. **三级自演化**：案例→模板→原则自动归纳，知识越用越精
4. **SafeSieve 闭环**：模板质量自动追踪淘汰，无需人工审核
