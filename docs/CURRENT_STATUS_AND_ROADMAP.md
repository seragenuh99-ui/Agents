## 一、这个系统在干什么（一句话）

你输入一道**研究/分析类题目**，系统像一个小团队分工：

1. **Planner** — 拆成几步  
2. **Retriever** — 查资料（内置知识库 + 以前做过的记忆）  
3. **Executor** — 必要时跑代码（很多题会跳过以省钱）  
4. **Summarizer** — 写成结构化报告  

**省钱的核心**：不是把字变短那么简单，而是**能复用上次结果就少叫几次 AI**。

## 二、关键名词（只看这一段就够）

| 词 | 通俗意思 |
|----|----------|
| **Token** | 发给 AI 的「字数费」，越大越贵、越慢 |
| **纯文本基线 A（49,076）** | 最笨的做法：四个 Agent 都用很长的大白话，也不记上次干了啥 |
| **无缓存 B（约 37,208）** | 用了结构化协议，但**每题都从零开始**，不记历史 |
| **全功能 C（约 16,300–17,600）** | 结构化 + **记忆库**，相似题直接套模板或整题复用 |
| **E2E（端到端复用）** | 两道题**几乎一模一样** → 上次整份答案直接拿来，**几乎 0 额外 Token** |
| **模板填空** | 题目很像但不完全一样 → 只让 AI **改差异部分**，不全重写 |
| **Dropout（甩 Executor）** | 不用写代码的题 → **跳过 Executor 那一次 AI 调用** |
| **热记忆 / 冷启动** | 热 = 同一数据库里**先做过几题**再做题；冷 = **清空记忆**每题独立 |
| **对抗题** | 故意出「看起来像旧题、其实要求不同」的题，测系统会不会**错用旧答案** |
| **质量 12/12** | 自动检查：有没有跑题、有没有明显错误、主题是否覆盖 |

### 3.3 实验矩阵 v2（core12 消融，2026-05-19）

**设计**：同一套系统，故意关掉某一功能，看 Token 变多少 → 知道「钱省在哪」。**24 题主数据以 3.2 为准。**

| 实验叫什么 | 干了什么 | Token（12题） | 省了多少（相对 49k） | 质量 | 说明 |
|------------|----------|-------------:|---------------------:|------|------|
| **C_warm 热记忆** | 12 题连着做、共用记忆 | **17,226** | **64.9%** | 12/12 | **最省的一种正常用法** |
| C_full 全功能 | 同上（略不同随机性） | 17,558 | 64.2% | 12/12 | 和主基准接近 |
| + LLM 裁判 | 多一层 AI 判质量 | 17,344 | 64.7% | 12/12 | 更严的质检，Token 几乎不变 |
| 关 E2E | 禁止「整题照搬」 | 19,472 | 60.3% | 12/12 | 少省 **~1,900** → E2E 有贡献但不大 |
| 无缓存 B | 不记历史 | 20,767 | 57.7% | 12/12 | 少省 **~3,500** → **记忆是最大头** |
| 关 Dropout | 每题都走 Executor | 22,352 | 54.5% | 12/12 | 少省 **~4,800** → **跳过 Executor 很值钱** |
| **C_cold 冷启动** | 每题清空记忆 | **22,131** | 54.9% | 12/12 | 比热记忆多花 **~4,900** |
| **full24（v0.9 旧）** | 24 道题 | **35,110** | 28.5%* | 24/24 | **现 v0.11.1：28,561**（见 3.2） |

## 四、三张图帮你想明白「钱从哪省」

### 图 1：相对最笨方案（49k），谁贡献了多少

```
纯文本 49,076 ████████████████████████████████████████ 100%
        ↓ 换结构化、短 prompt
无缓存 37,208 ██████████████████████████████            ~76%  （省 ~24%）
        ↓ 加记忆、模板、Dropout、E2E
全功能 ~17,000 ██████████████                            ~35%  （再省 ~55%）
```

**结论**：赛题要讲的重点是 **「记忆 + 少调 AI」**，不是「换了 MessagePack」。

### 图 2：全功能下，关掉谁最疼（12 题，v2）

```
热记忆 C_warm     17,226  ← 推荐用法基准
关 E2E            19,472  （+1,246）
无缓存            20,767  （+3,541）
关 Dropout        22,352  （+5,126）
冷启动            22,131  （+4,905）
```

**结论**：

1. **Dropout + 记忆** 是两大杠杆  
2. **E2E** 有收益但受「题目不够像」限制  
3. **用法**：同领域题**连续问**、别乱 `/clear`

### 图 3：质量 vs 省钱（目前阶段）

```

事实是否可查证   ████████░░░░░░░░░░░░  中等（模拟 KB）
抗「陷阱题」误缓存 ████████████████████  很好（0/6 误 E2E）
```

## 五、v0.10 Token 优化（已实现，2026-05-19 主基准）

| 改动 | 作用 |
|------|------|
| Orchestrator 统一 E2E | cos≥0.85 + 标签一致 → 整题复用（去掉重复逻辑） |
| 取消默认域内 LLM judge | 省每次 ~50 tok；改用 strategy 相似度 ≥0.68 注入 Planner |
| Summarizer 0.72–0.84 轻量适配 | 只花 ~280 completion，不全量生成 |
| Planner 模板「只改 query」 | 模板填空 prompt 更短，max_tokens 256 |
| 默认证据 600 字、摘要 512 tok | 压 completion |
| Executor Dropout 阈值 0.65 | 更多题跳过 Executor |
| Retriever 缓存阈值 0.88 + 标签 | 更多检索复用 |

复现：`python3 experiments/optimized_benchmark.py`

## 七、还能怎么优化（按推荐顺序）

下面每条都标了：**想解决什么 / 怎么做 / 预期 / 难度 / 是否已做**。

### P0 — 值得下一步做（改一点代码就能测）

| # | 方向 | 通俗说明 | 预期 | 难度 |
|---|------|----------|------|------|
| 1 | **换更大嵌入模型** | 用 `bge-base` 代替 `bge-small`，让「像但不完全一样」的题更容易命中模板 | Token 再降 **5–10%**；E2E 可能多 1–2 次 | 低（改环境变量 + 重跑矩阵） |
| 2 | **Summarizer 层 E2E** | 计划差不多、只是问法略变时，**摘要也复用**，不只复用 Planner | 多省 **1–2k** / 12 题 | 中 |
| 3 | **模板只填差异字段** | 模板填空时别让 AI 重写整份计划，只改 `delta` 字段 | completion 变短 | 中 |
| 4 | **阈值网格搜索** | 自动试 cos 0.82/0.85/0.88，找「省 Token 且对抗仍安全」的组合 | 数据支撑答辩 | 低（**脚本已加** `threshold_grid.py`） |
| 5 | **压 Summarizer 输出** | max_tokens 640→512、限制每条 finding 字数 | 方差变小，FULL_GEN 题更省 | 低 |

### P1 — 提「答得像真的」（质量向）

| # | 方向 | 通俗说明 | 预期 | 难度 |
|---|------|----------|------|------|
| 6 | **接真实 RAG** | 上传 PDF / 接搜索 API，Retriever 查真资料 | 事实性明显提升 | 高 |
| 7 | **CRAG 门控** | 检索结果不相关就别塞进 Summarizer，减少胡编 | 相关度 + 可信度 | 中 |
| 8 | **SafeSieve × 质量分** | 模板填空若上次质量差，下次自动降权 | 少「错模板」 | 中 |
| 9 | **证据蒸馏** | 同域多条记忆合并成一条短摘要再写报告 | prompt 更短 | 中 |

### P2 — 答辩与产品化

| # | 方向 | 通俗说明 |
|---|------|----------|
| 10 | **填人工 6 题表** | `docs/human_factcheck_pack.md`，答辩时说「自动 + 人工」 |
| 11 | **同域 5 题连跑演示** | 现场展示第 1 题贵、第 2–5 题变便宜（热记忆） |
| 12 | **对话模式当 Demo** | `python3 chat.py`，`/tags` 设领域 |
| 13 | **3-run 方差** | `multi_run_benchmark.py -n 3`，报告写「均值±标准差」 |

### 不建议再投入

| 方向 | 原因 |
|------|------|
| 加长 system prompt 蹭 KV 缓存 | 已证 completion 反而膨胀 |
| 无标签的 E2E | 跨域污染，对抗题会挂 |
| LatentMAS / 端到端训练 | 赛题约束下做不了 |
| 和单 Agent 比 Token | 单 Agent 4.5k 是「一次短答」，和多 Agent+记忆不是同赛道 |
