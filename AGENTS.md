# 702solver — Multi-Agent Shared Memory Diagnosis System

## Build / Run / Test

```bash
# Install deps
pip install -r requirements.txt

# Set API key
echo 'DEEPSEEK_API_KEY=sk-xxx' >> .env

# Run modes
python3 run.py                                          # interactive REPL (experiment console)
python3 run.py --mode 2 --suite core12                  # structured full-feature, 12 questions
python3 run.py --mode 1,2 --suite full24                # dual-mode comparison, 24 questions
python3 run.py --mode 2 --ask "your question"           # single question
python3 main.py demo                                    # offline demo (mock LLM)
python3 main.py experiment --mock                       # full comparison with mock
python3 main.py single "task description"               # single task
python3 chat.py                                         # interactive chat session

# Tests (run from repo root)
python3 -m pytest tests/ -v                             # all tests
python3 -m pytest tests/test_protocol.py -v             # single module
python3 -m pytest tests/ -x --tb=short                  # fast fail on first error
```

Tests require no LLM API key — all use `MockLLM` and deterministic hash embeddings.

## Architecture

```
main.py / run.py / chat.py          # CLI entry points
└── Orchestrator (src/orchestrator.py)  # central coordinator
    ├── PlannerAgent    → task decomposition, template-fill, domain-plan seeding
    ├── RetrieverAgent  → knowledge base + shared memory search
    ├── ExecutorAgent   → data processing, CodeAct (safe sandbox execution)
    └── SummarizerAgent → synthesize results, adapt cached summaries, evidence chains
```

**Three core mechanisms** (the contest requirements):
1. **Structured protocol** (`src/protocol/`) — MessagePack binary serialization with abbreviated field names. Messages carry action type, params, capabilities, optional embedding vectors. Replaces verbose natural-language agent communication.
2. **Non-text state passing** (`src/state/`) — BGE-small-en-v1.5 embeddings (384-dim) generated by `EmbeddingEngine`, routed via `StateExchangeBus`. Upstream agents (Planner, Retriever, Executor) call `transfer_state()` after completing their work to push embedding vectors to the bus. Downstream agents (Summarizer, Executor) call `get_packets_for(self.agent_id)` to pull those embeddings and use them directly for FAISS memory search — skipping the redundant "text → encode" round-trip.
3. **Shared memory** (`src/memory/`) — SQLite for structured metadata + FAISS IVF flat index for semantic similarity search. `MemoryUnit` has: id, source agent, timestamp, topic, summary, content, tags, evidence chain, embedding, access count, confidence, type (result/evidence/strategy/fact/error).

## Key Codebase Patterns

### Orchestrator pipeline (`execute_task`)
Plan → check E2E cache → seed plan from similar strategy → execute subtasks by dependency levels → summarize. Subtasks of the same role within a level run in parallel via `ThreadPoolExecutor`.

### Caching / optimization layers (`src/run_options.py` for flags, `src/task_intent.py` for intent gating)
- **E2E cache**: exact match on task embedding (cos ≥0.85) skips entire pipeline
- **Summarizer E2E**: cos ≥0.85 reuses past summary verbatim
- **Domain plan seeding** (`_load_domain_plan_hint`): loads strategy memory at cos ≥0.68, feeds Planner as template, avoids full LLM generation
- **Executor dropout**: when template fill score ≥0.65, skips executor agent entirely
- **SafeSieve**: records outcome of template reuse (success/failure) for feedback
- **Intent gating** (`cache_intents_compatible`, `blocks_executor_dropout`, `requires_fresh_synthesis`): prevents inappropriate cache reuse across semantically different tasks

### State Transfer end-to-end flow

```
Planner ──transfer_state()──→ StateExchangeBus._transfer_history
Retriever ──transfer_state()──→ StateExchangeBus._transfer_history
Executor ──transfer_state()──→ StateExchangeBus._transfer_history
                                      │
Summarizer ──get_packets_for("summarizer")──→ [StatePacket, ...]
              │
              ├── _build_query_embedding(): combine received embeddings
              │    or fall back to encode(task_desc) if no packets
              │
              └── FAISS memory_store.search_by_similarity(combined_emb)

Executor ──get_packets_for("executor")──→ [Retriever's StatePacket]
              │
              └── FAISS search for related past execution results
                   → injected into retrieval_results.memory_hits
```

**Sending** (`BaseAgent.transfer_state`): each agent encodes its result (`state_data` dict) as a 384-dim embedding via `EmbeddingEngine.encode_state()`, wraps it in a `StatePacket` addressed to the downstream agent, and pushes to `StateExchangeBus._transfer_history`.

**Receiving** (`StateExchangeBus.get_packets_for(target)`): downstream agent polls by its own `agent_id`, gets packets sorted newest-first. `mark_consumed()` removes them after use to prevent stale reuse across tasks.

**Consumption**:
- `SummarizerAgent._build_query_embedding()`: combines Planner+Executor embeddings (via `EmbeddingEngine.combine()`) for semantic memory search. Falls back to `encode(task_desc)` if no upstream state available.
- `ExecutorAgent.execute_task()`: uses Retriever's embedding to proactively search for related past execution results, injecting memory hits into `retrieval_results` for the processing step.

### Promoter (`_maybe_promote_to_template` in `BaseAgent`)
When N≥2 concrete memories of the same type + overlapping tags accumulate, synthesizes a domain template (abstraction_level=1) via LLM. Templates are searched first by Planner for template-fill instead of full generation.

### LLM backend (`src/agents/base.py`)
Supports `openai`, `deepseek`, `custom` providers. `.env` key names: `DEEPSEEK_API_KEY`, `OPENAI_API_KEY`, `OPENAI_BASE_URL`. `chat_structured` extracts JSON from responses via multiple fallback strategies (```json``` blocks, raw braces, etc.). Tracks prompt caching hit rates from DeepSeek's `prompt_tokens_details.cached_tokens`.

### Sandbox (`src/sandbox/executor.py`)
AST-level code validation before subprocess execution. Blocks dangerous imports (os, subprocess, shutil, sys, ctypes, socket, requests, urllib, http, ftplib) and dangerous calls (eval, exec, compile, open, __import__). 10s timeout, stdout/stderr capture.

### Testing conventions
- `tests/conftest.py` provides shared fixtures: `mock_llm`, component instances, timing helpers
- All tests use `MockLLM` — deterministic, no network
- Embedding tests use deterministic hash fallback when `use_real_model=False`
- Test files match `test_*.py` pattern

## Key Design Decisions

1. **Field name abbreviation** in protocol messages (e.g., `h.fr` for `from_agent`) to minimize binary size
2. **Deterministic hash embeddings** as fallback when `sentence-transformers` unavailable — ensures reproducibility offline and in Docker without HuggingFace download
3. **`RunOptions` frozen dataclass** — all caching/dropout/threshold knobs in one place, with `options_for_task()` providing per-task overrides for open QA vs closed tasks
4. **Intent-based cache gating** — classifies task intent (open QA, comparison, etc.) to prevent inappropriate cache matches; `blocks_executor_dropout` for tasks needing fresh computation
5. **Promoter threshold = 2** — after 2+ concrete memories with same tags, synthesizes a reusable domain template. This is intentionally low to quickly build template coverage with limited task throughput

## Known Gaps (codebase audit 2026-05-31, updated after third-pass audit)

Below are features where the skeleton/API is built but the implementation is incomplete
or the code path is dead. Ordered by impact.

### Gap 1: Message fields and enum values never consumed

`Message` carries `state_embedding`, `capabilities`, `context`, and `error` fields that are
serialized/deserialized but **never read by any agent or the orchestrator**:

| Field | Defined | Serialized | Consumed |
|-------|:-------:|:----------:|:--------:|
| `state_embedding` | ✓ | ✓ | ✗ (fixed for StateExchangeBus; still dead on Message path) |
| `capabilities` | ✓ | ✓ | ✗ |
| `error` | ✓ | ✓ | ✗ |
| `context` | ✓ | ✓ | ✗ |

11 of 16 enum variants across `MessageType` (8) and `ActionType` (3) are never dispatched:
- `MessageType`: RESPONSE, ERROR, HANDSHAKE, CAPABILITY_QUERY, CAPABILITY_ADVERTISE,
  STATE_TRANSFER, MEMORY_STORE, MEMORY_QUERY — all defined but never checked by any handler
- `ActionType`: STORE_MEMORY, REPORT, NOOP — never dispatched

`MessageBus.broadcast()` emits zero messages because `_queues` is empty when called
(during handshake, no agents have queues yet). `ProtocolParser.validate()` and
`ProtocolParser.create_error()` are defined but never called. `Message.serialize()` and
`Message.deserialize()` (msgpack path) are never used — all serialization goes through
`to_dict()`/`from_dict()`.

### Gap 2: SandboxExecutor and SandboxSession unused

`src/sandbox/executor.py` defines `SandboxExecutor` (in-process exec with restricted
globals) and `SandboxSession` (persistent subprocess with state across calls). Neither
class is imported by any production code. `validate_code()` is now wired into
`ExecutorAgent._run_sandbox()` (see Already Fixed), but `SandboxExecutor.execute()` and
`SandboxSession.execute()` remain test-only.

### Gap 3: Evaluation dead code

- `MetricsCollector.get_task_metrics()` — defined, never called
- `MetricsCollector.record_memory_store()` — defined, never called
- `MetricsCollector.record_llm_call()` — defined, never called (orchestrator uses `record_llm_usage()` instead)
- `Reporter.generate_comparison_table()` — defined, never called (main.py rolls its own)
- `Reporter.generate_markdown_report()` — defined, never called
- `Reporter.print_summary()`, `export_json()` — only used from experiments scripts, never from src/
- `TaskMetrics.messages_received` — always zero, never incremented

### Gap 4: EmbeddingEngine + StateExchangeBus dead utilities

- `EmbeddingEngine.decode_hints()` — structural analysis, defined but never called
- `EmbeddingEngine.estimate_bits()` — information content estimate, defined but never called
- `EmbeddingEngine.encode_batch()` — defined but never called (all encodings are one-at-a-time)
- `EmbeddingEngine.generation_count` — backing field never incremented, always returns 0
- `StateExchangeBus.receive_and_compare()` — debugging method, never called
- `StatePacket.to_dict()` and `StatePacket.cosine_similarity()` — never called externally

### Gap 5: Memory fields and methods not leveraged

- `MemoryUnit.confidence` — always defaults to 1.0, never updated
- `MemoryUnit.last_accessed` — tracked but never queried by business logic
- `MemoryUnit.to_search_text()` — defined but never called
- `MemoryUnit.from_dict()` — defined but never called
- `MemoryStore.get_hit_rate()` — defined, never called
- `MemoryStore._rebuild_index()` — defined, never called; `_dirty` flag never set to True
- `MemoryStore._embeddings` list — initialized but never populated (embeddings live in FAISS)
- `MemoryStore.clear()` — only used in test teardown
- HNSW index upgrade path (`faiss.IndexHNSWFlat`) — unreachable (100K vector threshold never hit)

### Gap 6: Architectural / deferred decisions

These are intentionally left un-fixed — they represent architectural alternatives or
scale-dependent optimizations, not missing functionality:

- `SandboxExecutor` and `SandboxSession` — alternative execution models; the current
  `validate_code()` + `subprocess.run()` combo gives AST validation + OS isolation
- `MessageBus.broadcast()` — structurally broken (no queues at handshake time), but
  the direct point-to-point routing matches the orchestrator's pipeline model
- `Orchestrator._build_dependency_levels()` — multi-level logic never exercised
  because all generated subtasks use `depends_on: []`; would activate with richer plans
- `Orchestrator._llm_judge_similar()` — gated by default-off `enable_domain_llm_judge`;
  domain plan seeding via `_load_domain_plan_hint()` already provides matching
- HNSW index upgrade path — unreachable at current scale (100K vector threshold)
- `RunOptions.enable_message_dispatch` and `enable_domain_llm_judge` — feature flags
  intentionally default-off for experiments
- `TaskIntent.COMPLIANCE` markers — match nothing in current benchmarks; ready for future task suites

### Gap 7: Minor dead code

- `BaseAgent.send_text_message()` — text mode goes through Orchestrator's `execute_task_text_mode()`,
  not agent-level messages. Kept as API for external text-mode experiments.
- `src/paths.py`: `log_path()` and `DEFAULT_CHAT_SESSION_DB` — path constants available
  but not used by current entry points
- `src/` init files: 5 of 6 `__init__.py` files are empty (valid Python packages)
- `Response` Messages: created by `send_response()` but only consumed for metrics counting,
  not for data flow. Results flow through direct function call returns by design.
- `MemoryStore._rebuild_index()` and `_dirty` flag — deferred optimization; FAISS index
  is rebuilt on next search if `_index is None`
- `MemoryStore._embeddings` list — unused alongside FAISS index
- `StateExchangeBus.receive_and_compare()` — debugging utility
- `StatePacket.to_dict()` and `cosine_similarity()` — utility methods
- `Orchestrator._count_messages_since()` — simple arithmetic helper
